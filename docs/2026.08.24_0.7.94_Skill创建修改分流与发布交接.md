## 2. 这次修的真实问题

用户原句：

> b2c-1v1-consultation，这个技能调用后的提示词是否可以修改。我的业务场景是，需要选中一个客户问卷，然后调用这个技能生成一份咨询方案。

旧逻辑把句尾业务产物“生成一份咨询方案”和前文的 Skill 拼成“生成 Skill”，Creator 抢走更新路由。模型因此只在普通聊天里解释应该怎么改，没有锁定现有 `SKILL.md`，也没有返回可执行的更新确认卡。

根因不是 Luna 不会修改，而是公开插件的确定性意图分流在模型之前选错了通道。

## 3. 0.7.94 的现行行为

| 用户表达 | 必须进入 |
|---|---|
| “把这套流程做成/提炼成/封装成一个 Skill” | 创建新 Skill |
| “修改/更新/优化 b2c-1v1-consultation 的提示词” | 锁定已有 Skill 后生成更新预览 |
| “调用 b2c-1v1-consultation，生成一份咨询方案” | 运行已有 Skill；“生成咨询方案”不是创建 Skill |
| 同一句确实同时要求创建和修改 | 先问“创建新的 Skill，还是修改现有的 Skill？” |
| 修改目标没有找到 | 先问是创建新 Skill 还是补充已有 Skill 完整名称 |
| 匹配到多个更新目标 | 列出候选并让用户给完整名称，不擅自选择 |
| 澄清回复“修改已有 Skill” | 继续最近锁定的更新上下文 |
| 澄清回复“创建新的 Skill” | 退出旧更新上下文，进入 Creator |
| 更新消息附带截图 | 截图只作为当前轮只读参考，不进入 Skill 包 |

创建和修改按同一小句里的直接语义判断。不能重新退化成“整条消息只要同时出现生成和 Skill 就算创建”的宽正则，也不能把业务步骤里的“更新客户档案”误当成更新 Skill。

## 5. 不可放宽的安全与产品边界

1. 更新前锁定一个准确的已安装 `SKILL.md`；不能用同名新建伪装覆盖。
2. AI 只提交结构化文本改动与删除；公开插件展示完整预览并由用户确认一次后才写入。
3. 确认前复核 Skill 全树指纹；并发变化立即停止。
4. 不创建 Skill 历史副本。写入中途失败只用本轮内存原字节恢复；检测到用户并发编辑时保留现场。
5. 更新不能新建或修改可执行脚本，也不能借截图扩大 Vault、联网、本机程序或写入权限。
6. Skill 默认按需读取当前整个 Vault；点名文件/文件夹只是本轮优先范围，绝不获得 Vault 外权限。
7. 并行对话和历史对话是独立产品能力，本次修复没有改变它们的会话模型、生命周期或 UI。

## 7. 下一次真实验收脚本

1. 在 Obsidian 更新到 0.7.94，完全重载插件。
2. 打开主对话，附上说明旧提示语的截图，并发送第 2 节原句。
3. 预期：直接锁定 `b2c-1v1-consultation` 并生成完整更新预览；不能只解释、不能进入新建、不能报“没有找到要修改的 Skill”。
4. 在预览卡继续用自然语言调整，确认后回读 `SKILL.md` 与 manifest，核对提示语和版本确实更新。
5. 再发“请创建一个新的 b2c-consultation Skill，同时修改现有的 b2c-1v1-consultation Skill 提示词”。
6. 预期：先出现创建/修改澄清；分别测试“修改已有 Skill”和“创建新的 Skill”，两条都应进入正确流程。
7. 最后发送“用 b2c-1v1-consultation Skill 生成一份咨询方案”。
8. 预期：运行现有 Skill，不进入 Creator，也不弹更新澄清。

任何一步失败，都先保存原句、截图、活动流和开发者控制台第一条错误；不要用重复发布或扩大权限掩盖路由问题。
