## 二、今天 Alina 报的三个问题（都已定位并修复，0.7.59）

### 问题 1：CRM「假成功」——AI 说"已加入 CRM"，数据库里查无此人

**现场**：学员 Ext.00668（木木）在插件对话里说"把客户加入 CRM"，AI 回复"已经登记在 CRM 里了"，但 CRM 里没有。Alina 一眼指出：真加成功会回客户编号。

**根因**（查 usage_log 证实：该账号当时段有 chat 调用、**零条 CRM 工具调用**）：
- 云端写入走两段式：判断轮输出 `<<<CLOUD_TOOLS_TURN>>>` → 插件补一个挂工具的执行轮。
- 执行轮的成功判定只有一条：`data.text` 非空（`src/main.ts` cloudToolsTurn 分支）。**模型光说话不调工具时，插件照样显示「✅ 云端写入轮完成」**。整条链路没有任何一处校验"工具是否真的执行了"。

**修复**（插件 + webapp 双端）：
- webapp `app/api/plugin/chat/route.ts` 非流式分支：从 `result.steps` 汇总本轮真实执行的 `toolCalls`，响应体新增 `executedTools: string[]`。拿不到 steps 时留空数组——**宁可让插件按"未确认"处理，不谎报成功**。
- 插件 `src/main.ts` cloudToolsTurn 分支：`executedTools.length === 0` 时不再显示成功，活动流记「⚠️ 本轮没有真正写入，已拦下」，并在回复末尾追加明确提示（没有真正保存 + 补救办法：重说一遍关键字段或去网页版手动录入）。提示文案遵守铁律：不提积分/计费/错误码。

### 问题 2：文件夹名对不上就找不到——"放到 output 文件夹"报错，因为真实目录叫 `03 output`

**根因**：`list_folder` 的路径解析是 `getAbstractFileByPath(path)` **逐字精确匹配**，对不上直接抛「没有找到文件夹」。AI 只能一层层 `list_folder` 去猜，烧轮次。

**修复**：
- `src/vault-agent-core.ts` 新增 `normalizeFolderKey()`：去序号前缀（`01_` / `03 ` / `③`）、忽略大小写、忽略 `_-. ` 与空格差异。
- `src/vault-agent.ts` 新增 `matchFoldersByName(root, query, loose)`，`list_folder` 精确解析失败时：唯一命中→直接用；多个命中→报错并列出全部候选路径让模型换准确路径重试；零命中→loose 模式找相近目录列进错误信息，**不再空手而归**。保护目录校验照旧在结果上执行，模糊解析不绕过任何权限规则。

### 问题 3：搜「小B」必返回 0 条——这是"反复说继续却不干活"的真凶

**现场**（她的截图）：`🔍 搜索「小B」→ 0 个相关文件`，但库里明明有 `2026.08.15_小B_产后健康管理教练.md`；而搜「小B 顾晓菲 沈立冬」有 8 条——靠另外两个三字名才凑出了 term。

**根因**（`src/vault-search-core.ts` buildSearchTerms 的旧正则）：

```
/[a-z0-9][a-z0-9._-]{1,}|[\p{Script=Han}]{2,}/gu
```

英文要求 ≥2 字符、中文要求 ≥2 连续汉字。**「小B」= 1 汉字 + 1 字母，两条都不匹配 → terms 为空 → 搜索必然 0 条**。她所有 demo 客户都叫小A/小B/小D，等于全部搜不到。下游连锁：搜索空手 → 模型只能逐层 list_folder → 20 步翻不完 → 撞轮次上限 → 只能嘴上说"继续处理"。**不是模型偷懒，是工具把它困住了。**

**修复**：
- tokenPattern 重写为：`/[\p{Script=Han}]+[a-z0-9._-]+|[a-z0-9._-]+[\p{Script=Han}]+|[a-z0-9][a-z0-9._-]*|[\p{Script=Han}]+/gu`——中英混合整体成词（小b、belinda妈妈）、单字母数字与其他字符相连时保留（vip-014）、单个汉字也成词。
- 新增 `GENERIC_SINGLE_HAN` 单字泛词表（的/了/我/这…），单独出现时过滤、作为混合词一部分时保留，防止召回被泛字污染。
- 打分阈值 `score >= 2.2` 验证过是健康的（正文单次命中最低 ~2.46，文件名命中 ≥10），**没动**。致命点只在分词——词被丢掉后，再合理的打分也没机会执行。

**回归**：`scripts/test-search-and-write-truth.mjs` 四组（短代号成词/单字泛词过滤/normalizeFolderKey 等价类/云端写入零执行必须拦截），已入 `npm test` 链。

## 三、架构层判断（回答她的"为什么 ChatGPT 能模糊匹配我们不能"）

不是权限没放开，也不是故意框死，是**手写检索的"严进"取向**：分词阶段就把"不像词"的输入丢掉，丢错即永久失联。成熟检索是**宽进严出**：先尽量召回，让排序去分高下，召回错了顶多排后面。我们没法上传笔记建索引（隐私铁律，本机检索是硬约束），但取向可以改。

**教训沉淀**：她的真实用例（客户代号小A/小B）从来没进过测试——我们一直拿三字全名测，恰好绕过坑。这是实现者视角的典型盲区。
