> 交接日期：2026-08-21

> 目标：在不改变现有能力、权限、数据与后端协议的前提下，把主对话界面改得更清爽、更像一个成熟的 Agent 工作台。

## 0. 先说结论

这次不要照搬 Ailu，也不要把 AI霖子改成面向开发者的 Codex/Claude Code 容器。

AI霖子的正确方向是：

> Ailu 一样清楚，Codex 一样自主，但普通创业者打开就能用。

Ailu 最值得借鉴的是交互原则：单一对话入口、上下文可见、复杂能力逐步出现、任务过程可追踪。AI霖子的差异化仍然是：商业教练判断、Vault 安全执行、CRM/任务、官方业务 Skill、积分与用户支持。

0.7.71 推荐做成一个低风险的“界面与入口重组版”。不改 API，不改模型路由，不改积分，不改 Vault 工具协议，不改 Skill 执行逻辑，不增加外部依赖。

## 3. 0.7.70 已有能力，界面开发不得误判为“尚未实现”

### 3.1 主对话与本地文件

- Luna 在合适的纯文字对话中自主决定是否请求受限本机工具；普通闲聊零预扫。
- 本机工具可搜索、列目录、读取受支持文件；文件改动必须经过结构化预览、本机预检、版本锁和二次确认。
- 当前笔记、主动选择的附件、受限 Skill 点名文件是三种不同授权来源，不能在 UI 上合并成“已授权整个 Vault”。
- 0.7.70 最新修复：明确限制只读当前材料的 Skill，可以根据用户写出的准确路径，只检查路径/文件名元数据并唯一锁定一份文件；歧义时停止，不扩大读取范围。

### 3.2 Skills

- 已有“调用技能”“我的 Skills”“创建 Skill / Skill Studio”。
- 已支持自然语言显式调用、Skill 名称调用，以及无可见面板的 `/技能名` 文本调用。
- 当前没有输入 `/` 后弹出的可视化命令面板。
- Skill 的创建、ZIP 导入、校验、试运行、输出目录和本地程序权限均已有完整安全流程。

### 3.3 图片

- 主对话已经支持自然语言生图、图片附件、图片批次编号、继续修改指定图片和自动保存到 Vault。
- 图片结果卡已有：
  - “继续修改这张”
  - “插入当前笔记”
- 文章配图已有候选预览、插入和重新生成。
- 当前尚无统一的“复制图片”“设为封面”“保存为品牌风格”操作；这些属于后续创作增强，不要在纯 UI 车次伪造按钮。

### 3.4 记忆与知识库

- 用户用自然语言说“请记住”时可以写事实记忆，服务端真实成功后才能回执。
- 用户用自然语言说“存入 AI霖子知识库”时走另一条知识库流程。
- 两者不是同一个目标，文案和 API 不得混用。
- 0.7.26 已明确取消普通回复下方常驻“存为笔记/更新当前笔记”和输入区常驻“存入知识库”。0.7.71 不得因为参考 Ailu 又把这些常驻按钮放回来。

### 3.5 任务过程

- 已有对话内活动流，真实工具动作才出现。
- 工作中显示旋转/呼吸动效；完成后保留最多 12 步，更多步骤显示折叠文字。
- 当前完成态仍以完整状态卡展示，不是可交互收起的摘要。

## 6. 0.7.71 推荐开发范围

### P0：必须完成的界面重组

#### A. 品牌头部

- 左侧：简洁品牌标识＋“AI霖子”。可以使用 Obsidian/Lucide 已有图标，暂时不要新增远程图片。
- 副标题缩短为“24 小时商业教练”或放在次级行。
- 右侧使用带 `aria-label` 和 tooltip 的图标按钮：历史、新对话、设置。
- 历史与新对话仍调用现有函数，不改变会话命名空间、持久化或删除规则。

#### B. 收起五个常驻按钮

推荐重组为两个入口：

- “技能”菜单：调用技能、我的 Skills、创建 Skill
- “工作台”菜单：内容看板、CEO 驾驶舱

菜单内部必须保留真实用户能理解的完整名称；不能只剩没有说明的图标。

#### C. 统一输入组件

- 把上下文状态、textarea、附件按钮、发送按钮装进一个统一的圆角 composer。
- 现有 `authorizedContentStatusEl` 可以改成 composer 顶部的可删除上下文标签，但只是重排 DOM/样式，不改变内容授权和清除逻辑。
- 保持 Enter 换行、Control+Enter 发送、Mac Command+Enter 兼容。
- 附件仍是最多 3 张图片或现有精确文件授权流程；不得因拖拽外观变化扩大文件授权。
- 发送按钮必须有禁用、发送中和键盘可访问状态。

#### D. 消息视觉层级

- 用户消息保留右侧强调色气泡。
- 普通 AI 正文改成更平的阅读样式，减少整块灰底。
- 确认卡、风险提示、图片结果、Vault 方案和 Skill 追问继续使用卡片，不得与普通正文混成一层。
- Markdown、代码块、表格、长文件名和来源链接必须仍可复制、换行、点击。

#### E. 空状态

- 未连接状态保留现在的三步连接引导和“打开插件设置”。这是功能门禁，不能为了简洁删除。
- 已连接状态缩成一句价值主张＋3 个可点击起手式，例如：
  - 处理当前笔记
  - 扫描知识库完成一项工作
  - 使用一个 Skill
- 保留 `chat.alinalinzi.com` 注册/积分入口，但降低视觉权重。

#### F. 活动流

- 工作中保持自动展开和动效。
- 完成/停止后显示一行摘要，如“已完成 · 8 步 · 36 秒”，详细步骤可以展开查看。
- 不改变 `ActivityFeed` 的动作记录、去重和本机历史边界。
- 不要用纯 CSS 隐藏所有内容导致用户无法审计；完成态必须可展开。

#### G. 响应式与主题

- 至少覆盖 320px、420px、600px 三种面板宽度。
- 覆盖浅色、深色和高对比 Obsidian 主题。
- 尽量使用 Obsidian CSS 变量；品牌强调色只用于关键动作。
- 所有新选择器必须限定在 `.ai-linzi-root` 或插件专属类，不污染其他插件和 Obsidian 编辑器。

### P1：可以同车完成的低风险入口增强

#### `/` 命令面板

输入框为空或光标位于开头时输入 `/`，显示本地菜单：

- 官方技能
- 我的 Skills
- 创建 Skill
- 内容看板
- CEO 驾驶舱

限制：

- 只调用现有函数，不新增服务端能力。
- 选择 Skill 后应填入现有确定性调用短语，或直接复用当前菜单行为；不能静默执行写入。
- 支持 Escape 关闭、上下键移动、Enter 选择、鼠标选择。
- 中文输入法合成期间不误触。
- 不保存用户 Skill 列表到云端。

如果 P0 完成后时间不足，`/` 面板宁可拆到 0.7.72，不要让它拖累主界面稳定性。

### P2：只记录，不在本车次实现

1. Obsidian 选中文字后“问 AI霖子/改写/总结”。
2. 图片“复制/设为封面/保存品牌风格”。
3. 每条回复的非侵入式“记住/沉淀”更多菜单；必须先与 0.7.26 的自然语言产品决定统一。
4. 后台任务队列、多会话并行、任务恢复和文件写入锁。
5. 内容编辑＋公众号/飞书/X 同步预览与发布工作台。
6. 本地持久化增量索引、向量搜索和跨 Agent 共享记忆。
