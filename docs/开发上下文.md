# AI霖子 Obsidian 插件开发上下文

> 本文是 Codex、Claude Code 和所有后续开发者的强制开发边界。修改插件或插件 API 前必须完整阅读；安全与产品边界不得以“临时兼容”“减少代码量”或“先上线再说”为由放宽。

## 1. 产品与代码边界：公开插件只是薄客户端

必须始终遵守：

> 公开插件只做界面、本地笔记操作和版本化 API 调用；真正有商业价值的提示词、AI 判断、计费、学员数据和模型编排全部放在私有后端。

公开插件仓库可以包含：

- Obsidian 界面、交互状态和用户主动触发的 Vault 读写。
- 请求参数、响应解析、错误提示与对服务端版本化 API 的调用。
- 不含商业机密的 Markdown 结构解析、TXT/PDF/DOCX 本地文字提取、公众号内联排版和本地安全校验。
- 可公开审查的隐私、安全、数据边界文档和回归测试。

公开插件仓库不得包含：

- AI霖子的核心系统提示词、商业判断规则、私有方法论提示词和隐藏验收标准。
- 任何具体模型的密钥、供应商密钥、真实内部接口或可绕过服务端计费的直连能力。
- 学员资料、长期记忆、账号权益、余额、扣费明细或其他服务端真相源数据。
- 模型选择、降级、重试、计费、风控和多模型编排的核心实现。
- 任何能让第三方仅复制公开仓库就复刻 AI霖子核心能力的代码或配置。

需要新增 AI 能力时，先在私有 AI霖子 webapp 后端实现，再通过 `/api/plugin/v1/*` 暴露最小必要接口。插件不能为省事复制后端提示词或直接连接模型供应商。

## 2. 用户数据与凭证

- 学员文档、配图和内容状态默认留在学员自己的 Vault。v0.7.18 起没有「带上当前笔记」勾选项：只有用户文字明确要求处理当前/这篇笔记，或继续上一轮已经锁定的当前笔记任务时，插件才读取单篇 Markdown，并向用户显示实际文件名；v0.7.21 起目标 Markdown 必须仍存在于打开的标签页中，关闭标签页立即撤销授权，禁止回退 `lastActiveFile` 或 Obsidian 最近打开记录，普通闲聊不读。v0.7.17 起也没有「智能搜索 Vault」开关，只有用户明确提出查找、读取、统计、整理、移动或删除 Vault/Obsidian/知识库/数字大脑/文件仓库中的文件，或继续上一轮已授权的 Vault 任务时，插件才允许本机工具按需读取 Markdown、TXT、可复制文字的 PDF 和 DOCX。普通闲聊不得预扫或发送 Vault 片段；不得建立云端索引或上传整个 Vault。用户主动打开精确选择器时，可以按 Vault 目录勾选整篇 Markdown 正文，但未确认的正文不得发送。
- 只有用户明确触发当前笔记任务、精确文件授权、喂库、配图、发布或更新笔记时，才读取和发送该动作所需的最小内容。
- Token、公众号 AppSecret 等敏感凭证必须进入 Obsidian `SecretStorage`；不得写入 `data.json`、日志、Git、报错文本或分析事件。
- 设置页不得暴露 `SecretStorage` 条目名或要求用户填写密钥 ID。AI霖子连接密钥和公众号 AppSecret 都使用单一密码输入框，内部固定条目名只属于实现细节。
- AI霖子云端负责账号、权益、积分、知识库、插件云端对话及模型调用记录；这些数据不得依赖 Alina 的个人电脑。
- 本地写入必须有明确的用户动作。更新当前笔记、应用局部补丁、覆盖图片与公众号发布都不得静默执行。
- 对话输入默认使用 Enter 换行，界面统一提示 Mac / Windows 使用 `Control + Enter` 发送；Mac 的 `Command + Enter` 继续作为兼容快捷键，用户也可点击右下角发送按钮。不得恢复为单按 Enter 直接发送。

## 3. 对话历史：插件到云端的单向可见性

目标关系：

- 插件产生的对话同步到 AI霖子云端，网页版可以查看这些对话。
- 网页版或微信端产生的对话绝不反向同步到 Obsidian 插件。
- 插件“历史”只显示插件产生的对话；支持单独删除一条或清空全部，但都只能删除插件产生的对话。

强制实现规则：

1. 插件会话 `sessionId` 必须使用固定前缀 `obsidian:`。
2. 插件的列表、读取、标题和删除 API 必须在数据库查询层同时限制当前 `student_no` 与 `session_id LIKE 'obsidian:%'`。
3. 禁止依赖客户端传来的 `channel` 作为唯一隔离条件；禁止插件删除接口只按 `student_no` 执行批量删除。
4. 网页端仍可读取学员全部合法云端会话，因此能看到插件会话；插件端只能读取插件命名空间。
5. 旧插件发送普通 UUID 时，新的插件聊天写入 API 在服务端补上 `obsidian:` 前缀。
6. 历史遗留的无前缀云端会话来源不可靠，插件必须排除，不能为了“看起来完整”而冒险显示或删除。本机缓存必须使用 Obsidian `Plugin.loadData()` 和 `Plugin.saveData()` 管理。
7. 插件单删和清空确认文案都必须明确说明：其他插件会话、网页版与微信端对话不受影响。

任何修改对话存储、恢复、跨端同步、单删或清空逻辑的提交，都必须同时运行客户端和服务端的会话隔离测试。

## 4. API 与后端边界

- 插件的新能力优先走 `/api/plugin/v1/*`；旧接口只做明确、限时的兼容，不继续扩张。
- 鉴权、授权、套餐校验、积分扣减、幂等、审计和访问范围必须由服务端执行，不能信任客户端 UI 状态。
- API 返回插件完成当前界面动作所需的最小数据，不把内部提示词、供应商响应、模型路由或学员完整档案返回客户端。
- 图片生成与主对话都走服务端 AI霖子模型编排。公开插件不得改成直连任何模型。
- 自 v0.6.48 起，主对话附件按钮可从 Vault 选图片或从电脑上传 PNG/JPG/WebP。图片在用户设备压缩后仅随下一条消息发送，单次最多 3 张；图片数据不写入插件历史或云端聊天历史。服务端必须再次校验类型、数量、大小与 Pro/Business 权益，并由私有模型编排切换到视觉模型。
- “AI 生图”只通过主对话自然语言运行，不再提供独立模式或图片设置面板。点击「继续修改这张」后，上一张必须作为主画布；用户没有明确要求改变画幅时保留原比例，明确要求改成另一平台比例时才允许重排。打开某篇笔记本身不得自动改走公众号配图、手绘流程图或固定信息卡模板；只有用户明确说要给当前笔记/文章配图时，才读取正文并进入文章单图流程。每张成功图片立即保存到用户 Vault，图片卡片和本地路径只保存在 Obsidian 管理的本机插件数据中，发送云端历史时必须剥离。云端只同步生图轮次的用户文字与不含图片地址的文字结果。
- 插件界面统一使用“AI 生图”这类能力名称，不显示或写死具体模型供应商，也不展示单次积分估算；模型可由私有后端以后独立替换。服务端仍必须对每张成功输出可靠记账，失败且没有产出时不记账。
- 小红书图文卡片的私有改写继续走 `/api/plugin/v1/skills/wechat-distribute`；单独运行卡片命令时只请求 `formats:["xhs"]`，不得顺带生成或扣取口播、朋友圈版本。服务端成品固定包含 3 个备选标题、300–800 字正文和 5–8 个话题词。公开插件只负责在本机按原文顺序解析全部 Markdown/Wiki/HTML 图片并与上下文混排，首图用于首页，其余图片不得默认独占一页；小红书 MD 按标题候选 → 正文/话题 → 卡片图片顺序保存。
- 主对话“AI 生图”和“我的专属人偶”只对 Pro/Business 开放；通用人偶的文章配图继续按原有技能权益使用。插件可以展示升级提示，但最终套餐校验必须由私有服务端执行，旧插件或篡改客户端不得绕过。
- 文章配图修改必须先显示原图与候选修改版，只有用户明确确认后才能备份并替换原图。补充参考图始终是可选项，用户只写修改要求也必须能完成流程。
- 公众号一键配图允许用户设置一张自己的专属人偶参考图。电脑上传的图片先保存进用户自己的 Vault，`data.json` 只记录 Vault 相对路径；只有用户主动生图时才压缩并随本次请求发送，服务端不得持久化原图、写入日志或返回其内容。参考图缺失时自动回退通用人偶。整篇配图、失败续跑、主对话补图与单图修改必须沿用同一设置。
- 只有用户明确提出“给当前笔记的 Part 4 补一张图、在这篇文章某段增加配图”等请求，插件才锁定并读取本轮单篇笔记，通过 `/api/plugin/v1/article-illustration` 的 `single` 模式生成候选图；仅仅打开笔记不是文章配图意图。候选图先在对话中显示，只有用户点击“插入当前笔记”后，插件才按服务端返回的逐字原文锚点写入原文章。
- 对话补图的文章判断、锚点选择、构图规划和模型调用全部在私有后端完成。公开插件只允许做意图路由、发送当前笔记、展示最小候选结果与用户确认后的机械插入；不得复制私有提示词或自行判断文章内容。
- 插件与网页端共享私有后端不等于共享客户端历史视图；每个客户端的读取与删除范围必须由服务端明确限定。
- 自动读取单篇当前笔记对 Starter、Pro、Business 全部开放，但 Starter 只允许用户明确点名处理的单篇纯文本笔记且受服务端字符上限保护；网页端通用文件上传仍为 Pro 权益。Vault 智能搜索只发送短片段，不等同多文件整篇上传；多笔记与文件夹整篇正文仍只能通过下述主动授权选择器使用。
- 自 v0.6.15 起，“选择文件”授权选择器对 Pro/Business 开放：用户通过 Vault 文件夹树浏览目录，在当前文件夹逐篇勾选，或明确添加当前文件夹及其子文件夹中的 Markdown 笔记；标题/路径搜索仍只在本地完成。v0.6.16 起目录树默认只展开一级，点击文件夹可展开或收起其子目录；Vault 参考图选择器必须保持相同的折叠交互。只有点击“授权给当前对话”后的正文才可发送；已选内容在本次对话的后续轮次持续带入，方便连续处理，但路径与正文都不得写入插件设置、本机对话缓存或云端历史。新建对话、切换历史、进入/退出访谈模式或点击清除时必须释放授权。
- 所有需要从 Vault 选择参考图的入口必须复用文件夹浏览器：展示 Vault 目录、当前目录图片缩略图和全局路径搜索，不能退回只有模糊文件名列表的选择方式。选择和预览全部在本地完成，只有用户明确发起生图时才压缩并上传已选图片。
- 主对话 AI 生图的 2.35:1、16:9、3:4、1:1 必须贯穿客户端与 `/api/plugin/v1/*` 协议。用户明确指定比例优先；否则公众号头条封面用 2.35:1、小红书封面/卡片用 3:4、普通横版用 16:9、方图用 1:1。服务端在供应商出图后统一交付为 900×383、1536×864、960×1280、1024×1024；比例后处理不再调用模型，不产生额外生图成本。
- 公众号文章封面必须由私有后端直接按接近最终成品的 1504×640（2.35:1）画幅生成，再无裁切缩放为 900×383；不得先生成普通 3:2 横图后裁掉标题。整篇配图写入笔记后，完成弹窗只负责退出遮挡，右侧对话必须保留“修改某一张配图”入口，供用户看过正文效果后再选择、预览并确认替换。
- 自 v0.6.21 起主对话支持整个 Vault 的本机检索；v0.7.17 起移除手动开关，改为只在明确 Vault 文件意图下进入受限工具循环，普通闲聊不预扫。索引仅在当前 Obsidian 进程内存中存在，不调用向量 API、不落 `data.json`。每轮结果仍受私有服务端数量与字符上限校验；回复下方的来源笔记按钮只保存在插件本机历史，云端历史不保存 Vault 路径。精确选择仍是另一条 Pro/Business 能力：单次最多 20 篇、单篇 50,000 字、已授权内容合计 120,000 字；同时带当前笔记时合计最多 160,000 字。整个 Vault 一键上传仍禁止。
- 自 v0.6.22 起，本地检索范围增加 TXT、可复制文字的 PDF 和 DOCX。TXT/PDF/DOCX 的文字提取器随插件打包并只在用户设备执行；不调用 OCR、向量 API 或云端解析。扫描版或加密 PDF、旧版 DOC、损坏文件，以及超过本地保护上限的文件会跳过并缓存为空，文件变更后再尝试。正文提取最多保留前 120,000 字，PDF/DOCX 同时解析并发必须受限，不能因大型 Vault 抢占 Obsidian。
- 自 v0.6.23 起，本地排序必须优先识别人名/项目名等稀有文件名词、用户明确说出的“今天/最新”、Raw 文件夹和文件类型，避免旧文档靠重复泛词挤掉刚加入的目标文件。来源按钮必须显示 MD/TXT/PDF/DOCX 类型。自动检索仍只提供短片段：用户要求总结或处理整份长文档时，服务端不得假装已经读完，也不得从无关片段或云端记忆猜测用户本地 SOP；应明确已找到的文件，并要求用户主动选择全文后再继续。
- 自 v0.6.24 起，Pro/Business 可在同一“选择文件”入口单选 MD、TXT、可复制 PDF 或 DOCX，并明确切换为长文任务。原文在用户设备提取、按段落切分，服务端一次只接收一段；每段成功后立即记录用量和扣分，最终合并单独记录和扣分。插件内存只保留当前任务的原文、分段和已完成摘要，失败时可从 `nextIndex` 续跑；不得写入插件本机持久化数据或云端历史。最终只同步用户任务说明和完整答复。扫描版 PDF 暂不 OCR，单份最多 40 万字、36 段，超限要求用户按章节拆分。
- 自 v0.6.25 起，删除“Vault 搜索排除文件夹”设置和旧版排除规则，用户 Vault 内全部正常 MD、TXT、可复制 PDF 和 DOCX 均可参与本机检索，包括文件名含特殊符号的普通文章。`.obsidian` 等点号开头的隐藏系统目录与 Obsidian 废纸篓不属于文章，仍在读取前跳过。升级时必须从 `data.json` 清理旧排除字段，不能让已经看不到的旧设置继续静默生效。
- 自 v0.6.26 起，来源文件在对话中统一显示为无边框的品牌蓝可点击文字，必须允许长文件名自然换行，不能恢复胶囊按钮。针对“某年某月有多少场咨询”这类可由文件列表确定的问题，插件先在本机按路径/文件名日期筛选咨询类逐字稿并按会话去重，把确定性统计结果作为单独上下文交给私有后端；模型不得仅根据最多 8 条片段猜总数。统计口径必须明确只覆盖已落盘逐字稿。开发辅助文件 `AGENTS.md`、`CLAUDE.md`、`_sub-agent-summaries.md` 与隐藏系统目录不属于用户文章，始终跳过。

- 自 v0.6.31 起，对话空状态承担新手引导：未配置连接密钥时显示三步连接引导与「打开插件设置」按钮（不允许让用户发消息撞报错才发现未连接）；已连接时显示与真实控件名一致的三个起手式。四处「未连接」报错共用 NOT_CONNECTED_MSG 一句话，禁止再出现「服务器地址/Token」等旧说法。寒暄与超短输入必须在扫描 Vault 之前短路（shouldSearchVault 前置），统计类长问题不受影响。会员门禁在缓存判无权益时必须强制刷新一次再拦截；更换连接密钥立即作废权益缓存。检索范围口径以 v0.6.25 条款为准：用户 Vault 全部内容（含文件名带「㊙️」的笔记）均参与检索，系有意设计（2026-07-30 Alina 确认，「㊙️ 跳过」只属于 Alina 自己大脑的云端同步场景）；AGENTS/CLAUDE 已同步修正。

- 自 v0.6.32 起，对话空状态的标题下所有文字必须放进 `.ai-linzi-empty-body` 统一容器（同字号 13px、同 380px 行宽、同左对齐），不允许再出现两套字号或宽度；空状态末尾固定保留网页版入口链接（chat.alinalinzi.com，注册/积分入口）。

### 4.1 插件 API 的长期兼容规则

- `/api/plugin/v1/*` 是插件的公开契约层，不得只是把网页端内部路由原样转发。每个 v1 入口必须负责校验稳定请求、归一化响应、附加 API 版本头，并把内部重构隔离在私有后端。
- 插件每次请求发送 `X-AI-Linzi-Plugin-Version`；服务端返回 API 版本、最低兼容插件版本和最新插件版本。设置页通过 `/api/plugin/v1/capabilities` 检查连接、权益与能力兼容性。
- v1 只能增加可选字段、增加不破坏旧客户端的能力，不得删除字段、改变既有字段含义或突然改变扣费语义。破坏性升级新开 `/api/plugin/v2/*`，v1 至少保留一个明确迁移周期。
- 新响应能力必须按插件版本渐进启用。例如配图的“保留成功图、只重试缺失图”只对声明支持的插件开放；旧插件继续获得旧语义，避免部分结果被丢弃却产生扣费。
- 配图规划是服务端和插件内部的短期任务状态，不得写成 Markdown 混入学员 Vault，也不得在报错中暴露构图提示。失败任务必须可按原方案继续补图；只有学员主动选择“重新规划”才重新生成方案。
- 对话单图结果可以作为插件本地会话中的候选卡片保留，但发送云端主对话时必须剥离图片候选元数据；云端只同步用户请求和文字回复，不能把本地文件路径、data URL 或待插入状态写进对话历史。
- 插件专用 API 必须有契约回归测试，至少覆盖：版本头、最低版本、能力清单、请求模式、部分成功、旧版兼容、鉴权/套餐/积分仍由服务端执行。
- 自 v0.6.3 起，插件的主对话、访谈写作、选题、公众号写作、多平台分发、谈单复盘、知识库和文章配图全部只调用 `/api/plugin/v1/*`。回归测试必须阻止插件源码重新出现 `/api/skills/*`、`/api/me/*` 或未版本化 `/api/plugin/chat`；网页版继续使用原接口，二者互不替换。

## 5. 每次交付前的最低验收

- `npm run build`
- `npm test`
- 服务端插件会话隔离测试与生产构建通过。
- 检查 Git 变更中没有真实 Token、AppSecret、模型密钥、学员数据、核心提示词或内部模型编排。
- 检查插件删除接口在没有 `sessionId` 时仍保留 `obsidian:` 查询条件。
- 检查网页版对话 API 没有被改成只读插件会话；单向可见性必须保持。
- 检查未确认的笔记正文不会发送，授权内容不落设置/历史，新建或切换对话会清空；Starter 绕过客户端提交多笔记时服务端返回 403。
- 把构建后的 `main.js`、`manifest.json`、`styles.css` 安装到测试 Vault，重启 Obsidian 后实测历史列表、恢复、单删和清空。

## 6. 仓库与发布

- 公开仓库：AI霖子 Obsidian 插件薄客户端、公开文档、测试与发布包。
- 私有仓库：AI霖子 webapp、核心提示词、计费、学员数据、模型编排与插件服务端 API。
- 手动安装包统一命名为 `ai-linzi.zip`，ZIP 根目录直接放 `manifest.json`、`main.js`、`styles.css` 等文件。不要再在 ZIP 内包一层 `ai-linzi`，否则 Windows“全部解压”会形成双层目录，Obsidian 无法在 `plugins` 第一层发现插件。
- 官方市场版不得包含插件自更新机制；更新统一交由 Obsidian 官方插件市场和 GitHub Release 处理。
- GitHub Release 的标签必须与 `manifest.json` 版本完全一致，使用 `0.6.28` 这类纯版本号，不加 `v` 前缀。
- 两个仓库独立提交、独立审核和独立发布。修改插件不得顺手改变网页版 UI；修改私有后端必须确认现有网页端接口不回归。
- 发布前先检查本文件；若产品决定改变这些边界，必须由 Alina 明确批准并同步更新本文件、`AGENTS.md` 与 `CLAUDE.md`。
