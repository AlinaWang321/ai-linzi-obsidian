## 7. 未完成项与已知风险

### 7.1 本轮发现的两条 CSS 铁律（建议沉淀进 AGENTS.md）

这两条都是**只有真机才会暴露、原渲染台抓不到**的，各自都已有守卫测试：

**① 选择器权重必须达到 (0,3,1)。** Obsidian 与主题普遍带 `button { padding; border-radius; background }`，深色主题常写成 `.theme-dark button`（0,1,1）甚至更高。首轮实测：单类写法下发送键 `border-radius` 被改成 5px、`padding` 被改成 4px 10px，**根本不是圆的**；深色下三处按钮背景全被刷回灰底。市场检查禁用 important 声明，权重是唯一杠杆，因此统一写成 `.ai-linzi-root <祖先类> button.x`。`@container` 内的规则同样要写足。

**② 权重只能覆盖「声明过的属性」。** 主题 `button` 规则里还有 `height` / `white-space` / `line-height`，我们没声明的那几条，权重再高也拦不住——起手式卡被压成固定 30px 高，第二行说明文字溢出被下一张卡盖住（Alina 截图报障）。现由一条共享 reset 显式声明 `height:auto / min-height:0 / max-height:none / white-space:normal / line-height / font-family:inherit`。

### 7.2 已知风险

- **容器查询**：窄面板断点用 `@container`（`@media` 判的是视口，Obsidian 侧边栏是宽窗口里的窄栏，永远不命中）。需要 Obsidian 的 Electron 支持 CSS 容器查询——minAppVersion 1.11.4 对应的 Electron 版本请 Codex 复核一次。
- **`main.js` 体积**：内联头像使 base64 增加约 19 KB（2937 → 2958 KB）。已由 `test-brand-assets.mjs` 卡 40 KB 上限防止后人塞原图。
- **`addIcon` 用 `<image>` 内嵌 PNG**：语法合法且不含远程地址，但官方市场审核器对 base64 blob 的态度未经实测。建议发版前用「Preview a branch scan」扫一次。
- **验收库 manifest 写的是 `0.7.71-rc.1`**，仓库正式 manifest / package.json 仍是 `0.7.70`，未改。**不要在验收库点「检查并更新」**，市场最新版是 0.7.70，会把候选覆盖掉。
- **紫色用户气泡未调整**，等 Alina 看过真机后决定。

### 7.3 我在本轮犯的两个错误（供审核时警惕）

- 做哨兵验证时用 `&&` 串「改坏 → 测试 → 恢复」，grep 无输出导致链条中断、恢复未执行；随后 `git checkout -- styles.css` 回退，**丢失了未提交的 CSS 改动**。已从渲染台副本逐项核对恢复（5 个关键标记全部比对）。此后所有哨兵验证改为无条件恢复。
- 一次「测试通过」的报告是错的：把 `$?` 取成了管道里 `head` 的退出码而非 `node` 的，实际测试正在崩（JS 的 `RegExp` 不支持 `(?m)` 内联标志）。此后所有测试统计都先跑、再单独取退出码。
