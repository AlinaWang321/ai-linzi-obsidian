# 0.7.73 开发与验收方案

> 状态：代码、完整自动化门禁、市场扫描、候选打包和测试 Vault 安装已完成；macOS 锁屏导致真实 Obsidian 交互验收待补。未打标签、未建 Release、未抬生产 latest。范围只包含“我的 Skills”安全升级、版本历史/恢复，以及多资料候选选择；不改变普通 Vault 写入、脚本执行或发布边界。

## 目标

1. 允许用户在 Skill Studio 里选择一个已安装 Skill，说明要修改什么，并让 AI 生成版本化更新方案。
2. 更新前展示写入、删除和完整内容差异；用户确认前不改文件。
3. 确认时重新核验整个 Skill 的路径、mtime、size 和 SHA-256；任何并发变化都停止。
4. 先在 `<skill>/ai-linzi-versions/<时间戳>__<版本>/` 保存可校验的全量二进制快照，再通过 Obsidian Vault API 更新正式文件。该目录必须对 Vault API 可见；不用 Adapter，也不用点号隐藏目录。
5. 任一步失败都按快照恢复并逐文件校验；只有成功后才保留最近 5 份历史。
6. 版本历史支持恢复。恢复前同样先备份当前版本、再次确认、失败回滚。
7. Skill 允许搜索资料时，只有模型真实请求本机搜索后才可列候选；多份候选必须让用户按准确路径选择，不能预扫或猜文件。

## 不放宽的边界

- `references/ai-linzi-skill-manifest.json` 的 `skillVersion` 是版本真相源。
- 更新协议只允许 `SKILL.md`、`references/`、`assets/` 下的普通文本；本车次不让 AI 新建或改写可执行脚本。
- `deleteFiles` 单独列出、单独校验、在确认卡中逐项展示；`ai-linzi-versions`、隐藏路径和 Skill 根目录外路径永远拒绝。
- 版本历史只保证当前设备可用，暂不承诺跨设备同步。
- 读取、搜索、列目录无需确认；创建、更新、删除、恢复仍需用户确认。脚本执行继续默认关闭且逐步确认。
- 不新增依赖，不增加构建产物动态 `<script>`、`eval` 或 `new Function` 基线。

## 阶段门禁

1. 协议与纯逻辑：路径穿越、版本倒退、重复路径、删除 manifest、超限、无变化方案全部失败关闭。
2. 事务行为：并发变化、二进制快照、写入中途失败、删除中途失败、回滚时用户并发编辑、快照校验、成功后清理第 6 份历史。
3. UI 行为：完整预览、删除显著提示、按钮防重复、失败恢复可点、设置目录变化拒绝、恢复二次确认。
4. 完整门禁：`npm run build`、`npm test`、`npm run check:marketplace`、`npm run package:release`、生产包启动烟雾。
5. 原生验收：安装进“数字大脑”测试 Vault，实际跑升级、并发冲突、失败回滚、历史恢复和多候选选择；回读文件与 SHA-256。

## 发布边界

开发提交和测试 Vault 候选安装不等于正式发布。本轮只有在自动测试、发布产物扫描和原生验收全部通过后，才具备上架条件；未获得最终发布指令前不打标签、不建 Release、不抬生产 latest。
