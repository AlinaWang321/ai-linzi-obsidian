# A. 经营周报看板重设计

## A0. 结论先说

现在的 `artifactDashboardHtml()` **配色是对的**（水·木·光色号全部取自品牌令牌，没问题），
**信息设计是错的**。不要重调颜色，要重排信息。

三个致命问题：

| # | 现状 | 后果 |
|---|---|---|
| 1 | 全部内容藏在标签页后面，首屏只能看到 1/7 | 打开看板要点 7 次才看完，等于没有"一眼" |
| 2 | 所有卡片长得一模一样（同底、同圆角、同字号） | 「今天必须做的 3 件事」和「跳过的文件清单」视觉权重相同 |
| 3 | 表格原样渲染，没有任何图形 | 「线索 34 / 咨询 9 / 成交 3」是本页最重要的信息，却是一张灰表格 |

还有一个真 bug：**进度条把「昨日完成」里已经打勾的历史 `[x]` 也算进了完成率**，
所以首屏显示 "2 / 11 项完成 · 18%" —— 这个数字没有任何意义。

## A1. 新版信息结构（替换标签页）

顺序即优先级，从上到下单栏流式，左侧一条 sticky 导航轨（滚动高亮），不再分页：

```
① 驾驶舱头   标题 + 时间范围 + 判断金句（宋体）+ 覆盖率条
② 今天做什么  ← 唯一可勾选区，进度环只统计这里
③ 漏在哪一步  ← 经营链路漏斗（核心图）
④ 本周数字    ← 指标卡 + 环比 + sparkline
⑤ 七天节奏    ← 7 列日历条
⑥ 昨天发生了什么  ← 静态回执，不可勾选
⑦ 下周决策    ← 编号行动 + 不做清单
⑧ 数据依据    ← <details> 默认折叠
```

关键改动逐条：

**② 今天做什么**
- 提到第二屏，卡片顶部 3px 暖金边（全页唯一一处大面积用金）。
- 进度环（SVG donut）**只统计 `## 今日待办` 下的 checkbox**。
- `data-core="1"` 标记「今天必须推进」的项；左轨徽章显示 `已完成/必须做`，不是全部。
- 两档之间用 tier 分隔行（暖金点 = 必须，海蓝点 = 完成一项即可）。

**③ 漏在哪一步（新增，最重要）**
`## 经营链路` 的表格不要再渲染成表格，渲染成漏斗：
- 每一档一根横条，宽度递减，填色走**单色阶** `--fn1…--fn5`（水家族 light→dark）。
- 条内直接标数字（`11 篇` / `34 人` / `9 场`）；右侧标上周值。
- **两档之间那行才是重点**：转化率 + 环比。转化率环比下降最多的那一档，
  整行转陶土色并挂 `最大漏点` 徽章。
- 底下一句话结论，把"卡在哪"用陶土色加粗点出来。

这一张图是整个看板存在的理由 —— 它回答"钱从哪一步漏掉"。

**④ 本周数字**
- 每个数字必须带环比 `▲/▼`（青碧=向好，陶土=变差，灰=持平）。
- 有日粒度数据的指标画 sparkline（面积 + 2px 线 + 端点圆），没有就不画，别硬凑。

**⑤ 七天节奏**
`### 每日进展` 表格 → 7 列卡片：日期 / 柱（高度=当天线索数）/ 主线 / 结果 chip / 一句话。
当周最高那天柱子转青碧（`.peak`）。

**⑥ 昨天**
历史 `- [x]` **不渲染成 checkbox**，渲染成静态 ✓ 圆点回执；`- [ ]` 渲染成虚线圆点 + 灰字。
理由：已经发生的事不该能被点掉，也不该混进今天的进度。

**⑧ 数据依据**
折叠。展开后除了文件表，底部固定一个口径提醒框（见 B 部分 #7 的 mtime 警告）。

## A2. 视觉规格（照抄参考稿的 :root 即可）

- 三态主题必须齐：`:root`（浅色基准）/ `@media(prefers-color-scheme:dark){:root:not([data-theme="light"])}` / `:root[data-theme="dark"]`。
- **禁止把颜色只写在 media 或 [data-theme] 里**，也禁止内联十六进制。
  我第一版就踩了：漏斗条内联了 `#293857`，浅色好看，暗色直接消失在深底上。
  所有色都必须是令牌，暗色重定义令牌本身。
- 文字对比度实测（cream 底）：
  - 青碧 `#3DB389` 作文字只有 2.44:1 —— **不合格**，正向文字用 `#237A5C`（4.86:1）。
  - 暖金 `#F5C518` 作文字 1.51:1、深金 `#D4A50C` 2.12:1 —— **浅底上金色永远不做文字**，
    只做小色块/边条，且旁边必须有墨色标签。这条和品牌「暖金只点睛」是同一条。
  - 陶土 `#B0532F` 4.73:1 ✅；海蓝 `#2E5A8F` 6.56:1 ✅。
  - 暗底反过来：青碧 `#6FD9B0` 9.82、暖金 `#F5C518` 10.92、陶土要换成 `#E08A5F`（6.40）。
- 字体：**不许引外链字体**（离线文件铁律）。中文 PingFang SC 栈，
  数字单独一个 `--num` 栈 + `font-variant-numeric:tabular-nums`，金句才用宋体斜体。
- 动效：入场生长（漏斗条 scaleX、日柱 scaleY）+ 环形进度过渡，就这些；
  `prefers-reduced-motion` 全关。
- 打印：左轨隐藏、`<details>` 全展开、阴影去掉、卡片 `break-inside:avoid`。
- **`<meta name="viewport">` 必须保留** —— 参考稿在浏览器里测时因为少这行，
  移动端 layout viewport 被强制成 980px，媒体查询全部失效。渲染器现在有这行，别删。

## A3. Markdown → 语义的映射契约

渲染器拿到的是任意 Markdown，所以要定一份契约，同时**每一条都要有降级路径**
（匹配不上就退回现在的通用卡片，绝不能白屏）：

| Markdown 特征 | 渲染成 |
|---|---|
| 首个 `#` 前的 `> 引用` | 判断金句条 |
| 首个 `#` 前的 2–3 列表格 | 指标卡组（第 3 列 = 环比，识别 `▲▼/+-/%` 出方向色） |
| `> 扫描 N 份，完整读取 M 份，跳过 K 份` | 覆盖率条（正则抽 3 个数） |
| `## 经营链路` 内的表格（含「环节/本周/上周」列） | 漏斗 |
| `## 今日待办` 下的 checkbox | **唯一**可勾选 + 进度环；`### 今天必须推进` 下的记 core |
| `## 昨日重点` 下的 checkbox | 静态回执，不进进度 |
| `## 七天轨迹` → `### 每日进展` 表格 | 7 列日历条 |
| `## 数据依据` | `<details>` 折叠 |

配套要改 `src/skill-studio-core.ts` 里 `weekly-dashboard-spec.md` 的 Markdown 模板：
经营链路表加「上周」列，指标表加第 3 列环比，每日进展表加数值列。
**模板改了才有数据画图**，只改渲染器没用。

## A4. 落地范围

只动这两个文件：
- `src/artifact-renderer.ts` → `artifactDashboardHtml()`（整体重写）
- `src/skill-studio-core.ts` → `weekly-dashboard-spec.md` 的表格列

`document` 版式不动，docx/pdf/pptx 不动。

# B. 0.7.68 代码审计（按严重度排序）

## B1 · 🔴 `02_Wiki` 被硬编码进了要上架的插件

`src/main.ts:3742` 咨询闭环预读：

```ts
arguments: { path: '02_Wiki', depth: 1, offset: 0, maxEntries: 160 }
```

`02_Wiki` 是 Alina 自己 Vault 的目录名。任何别的用户装了插件跑这个 Skill，
这次 `list_folder` 必然失败，每轮多一条失败工具结果。
**改**：先无参 `list_folder` 列根目录，再按名称启发式挑候选客户库；或从设置读。

## B2 · 🔴 预读把用户的「客户档案模板」加进了 `verifiedWritePaths`

`src/main.ts:3778`：

```ts
for (const source of templateCandidates) {
  const stat = this.plugin.vaultFileStat(source.path)
  if (stat) verifiedWritePaths.add(source.path)   // ← 模板文件
}
```

`verifiedWritePaths` 的语义是「已核对过原文，`replace_note`/`update_note` 可以直接出确认卡」。
把模板文件放进去，等于**恰好在 SKILL.md 明令禁止写入的那一类文件上，把安全网撤掉了**
（SKILL.md：「不得把客户档案写进模板目录」）。用户仍需点确认，但少了一道客户端复核。
**改**：预读模板只 `sources.push`，不进 `verifiedWritePaths`。

## B3 · 🔴 引擎不对称：`read_recent_documents` 在原生通道根本不存在

- 原生 function-calling 通道白名单（`src/main.ts:3999`）只有
  `vault_search | list_folder | read_note`，遇到 `read_recent_documents` 直接
  `throw new Error('native: unsupported tool')`。
- 自动追页逻辑（`src/main.ts:4616`）也只写在散文通道。
- 但 SKILL.md 向模型承诺「AI霖子 0.7.68+ 会在本机自动追完文件分页和长文字符分页」。

结果：走原生通道时这句承诺是假的，只能靠回退救。这和记忆里
`obsidian_plugin_0742_full_vault_ops` 记的「引擎不对称（0.7.49 修复漏在回退路径）」
是同一类复发。**改**：白名单加 `read_recent_documents`，追页逻辑抽成共用函数两边都调。

## B4 · 🟠 同一个 Skill 两套读取预算

- 散文通道：`appendToolResults` 传了 `WEEKLY_BUSINESS_DASHBOARD_MAX_RESULT_CHARS`（100 万）。
- 原生通道 `src/main.ts:4050`：`appendToolResultsWithinBudget(toolResults, executed.results)`
  —— **没传 cap，用默认 36 万**。

同一份周报，走哪条通道决定了它能读多少，用户无感知。**改**：预算按 skill 决定，
不按通道决定，抽一个 `budgetFor(localSkill)` 两边共用。

## B5 · 🟠 每条回复都被静默改格式（波及全插件，不只咨询闭环）

`src/main.ts:3201` 无条件对**所有**回复执行：

```ts
const consultationBriefAction = extractConsultationBriefAction(answer)
answer = consultationBriefAction.cleanText || (...)
```

而 `extractConsultationBriefAction` 里有 `.replace(/\n{3,}/g,'\n\n').trim()`。
实测（无标记的普通回复）：

```
输入: "第一段\n\n\n第二段\n\n\n\n```js\nconst a=1\n\n\n\nconst b=2\n```"
输出: "第一段\n\n第二段\n\n```js\nconst a=1\n\nconst b=2\n```"
```

代码块内部的空行也被吃掉了。公众号排版、脚本、诗歌类输出都会受影响。
另外 `runCustomerConsultationBrief` 的触发条件只看标记在不在，
没有校验 `localSkill?.name === CONSULTATION_WORKFLOW_SKILL_NAME`。
**改**：整段逻辑加 skill 名门禁；`cleanText` 的归一化只在 `requested === true` 时做。

## B6 · 🟠 自动追页遇到截断会静默停

`src/main.ts:4620` 追页循环靠 `JSON.parse(current.output).nextOffset` 决定是否继续。
但 `outputJson()` 在超过 `RECENT_DOCUMENT_OUTPUT_MAX_CHARS`(10 万) 时会返回
`{truncated:true, preview:"…"}` —— 能 parse，但没有 `nextOffset`，于是 `break`。
追页在半路停下，而模型侧看到的是一份"读完了"的结果。
单页正文上限 7 万字，JSON 转义后通常不到 10 万，所以是**低概率但静默**——
最坏的一类。**改**：`truncated === true` 时不要 `break`，要注入一条显式的
"本页结果被截断，未读完"工具结果，让模型必须如实报告。

## B7 · 🟠 「最近 7 天改动」在她这台机器上必然被污染

`read_recent_documents` 用 `file.stat.mtime >= cutoff` 判定"本周动过"。
但这个 Vault 有一堆定时任务会批量改写文件：
每周一 8:00 的 `sync_crm_dashboard.py` / `sync_camp_summary.py` / 教练班看板、
Substack 抓取、以及任何一次 `git pull`。
**周一早上跑周报，会把上百个被脚本刷过 mtime 的文件当成"本周经营动作"。**

**改**：至少三选一 —— ①优先用 frontmatter 日期/文件名日期，mtime 只做兜底；
②排除一批已知的自动化产物目录；③在覆盖率条旁明确标注"按文件修改时间统计，
批量脚本会影响口径"（参考稿的 `.warnbox` 已经写了这句）。

## B8 · 🟡 周报会读自己的产物

排除清单只排掉了 `$OUTPUT/经营周报`，`$OUTPUT` 下其他目录（客户咨询简报、
公众号排版 HTML、插图、PPT）全都在扫描范围内。周报于是在读 AI 自己上周的输出，
再总结成"本周进展"。这和「RAG 纯净度：草稿物理隔离」是同一个原则。
**改**：默认排除整个 `$OUTPUT` 根，或给设置里加一个排除目录列表。

## B9 · 🟡 分页游标不稳定

`read_recent_documents` 每次调用都重新 `getFiles()` 并按 mtime 重排，
分页 `offset` 是这个动态列表的下标。翻页期间只要有任何一个文件被写入
（Obsidian 自动保存当前笔记、同步、插件自己写日志），排序就变，
**会静默跳过或重复文件**。
**改**：首页把文件路径清单快照进返回值，后续页按快照走，不重排。

## B10 · 🟡 create-note/create-artifact 的空转纠正被削弱

`src/main.ts:4416`：只要 `toolResults.length > 0`，create-note / create-artifact 类 Skill
的 stalled 判定就一律降级成 `deferred_answer`，不再走
`vaultWriteFlowRetryReason` 的 `stalled_write_flow` / `missing_tool_use`。
0.7.66 刚刚根治「空承诺循环」，这里等于对一整类 Skill 放开了同一个口子。
**建议**：至少保留 `missing_tool_use` 那一支（完全没建立任务时仍要强纠正），
只把 `stalled_write_flow` 降级。

## 顺带说明

- `npm test`（52 个脚本）、`tsc --noEmit`、`eslint src --quiet` 本地**全绿**。
  上面所有问题都是测试抓不到的 —— 因为现有测试大多是对源码做 grep，
  不真跑渲染、不真跑分页。B6/B9 尤其需要真跑的单测。
- `dece51a`（Skills 目录改名后重新确认）实现是对的，没有问题。
- **成本实测（2026-08-20 用生产数据重算，替换初稿里按 DeepSeek 估的说法）**：
  插件主对话现在实际走 `gpt-5.6-luna`（`app_config.plugin_chat_model_id`，2026-07-30 起）。
  实测 Alina vault 内容 o200k **0.682 tokens/字符**（抽样最近 7 天 60 份最大 md，97 万字符）。
  Luna 定价：短上下文 ¥1.44/M 输入、¥8.64/M 输出；**输入 > 272,000 tokens 时整次请求翻倍**
  为 ¥2.88/M 输入、¥12.96/M 输出。按每次跑 2 轮满上下文估算：

  | 字符上限 | 单轮输入 tokens | 计价档 | 每次约 |
  |---|---|---|---|
  | 27 万 | 209K | 短 | ¥0.65 |
  | **36 万（现默认）** | **270.5K** | **短（只剩 1,480 tokens 余量）** | **¥0.83** |
  | 50 万 | 366K | 长 | ¥2.19 |
  | 100 万（0.7.68 现值） | 707K | 长 | ¥4.15 |

  **关键：36 万这个默认值恰好卡在 272K 分界点下方，只剩约 2,200 字符的余量。**
  系统提示、Skill 文件或 RAG 只要再长一点，整个请求就翻倍计价。
  这个余量必须显式守住——建议把预算改成按 **token 预算（上限 260,000）** 而不是字符数，
  并在超限时如实回报"未读完 N 份"，别悄悄涨到长上下文档。

- **🔴 附带发现：插件的 prompt cache 命中率是 0**。
  近 10 天 3,378 次 luna 请求、8,650 万 prompt tokens，账面成本与"零缓存全价"
  逐分钱吻合（saving = 0.0%）。`lib/chat-core.ts:720` 是有读 `cacheReadTokens` 的，
  说明是 API 真的没返回命中，不是记账漏了。
  vault 循环每轮都整包重发 toolResults，正是缓存收益最大的场景——命中的话
  第 2 轮起按 ¥0.288/M 计，等于打一折。
  请排查请求前缀里有什么每次都在变（`round` / `retryReason` / 时间戳 / sessionId
  的注入位置），把可变段一律挪到最后一条 user 消息尾部（这本来就是
  `ai_linzi_context_injection_architecture` 定的架构）。**这条比调预算值钱得多。**
